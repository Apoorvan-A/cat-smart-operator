# Assumptions

Owner: Claude 4. Every non-real capability must appear here. Categories:
`KNOWN | FROM PROBLEM STATEMENT | ASSUMED | SIMULATED | PREDICTED | FUTURE REAL INTEGRATION`.

## FROM PROBLEM STATEMENT
- Telemetry fields: timestamp, machine id, operator id, engine hours, fuel used,
  load cycles, idle time, seatbelt status, safety alert triggered.
- Required outcomes: daily task dashboard, safety features, training hub,
  unusual-usage detection, task time estimation.

## KNOWN / DESIGN DECISIONS
- Safety-critical logic is deterministic (rules), never LLM-driven.
- The LLM assistant is an explanation layer only; it has no DB access.
- ML runs as a separate service with deterministic fallbacks.

## ASSUMED
- Seatbelt, proximity, and slope sensors exist and report at telemetry cadence.
- A proximity threshold of 5 m for workers, 8 m for vehicles (configurable).
- Idle > 45 min while a task is assigned is operationally "excessive".
- One operator ↔ one active machine per shift.
- Sites have a single weather profile at a time.

## SIMULATED
- **All** telemetry, weather, proximity events, worker/vehicle positions, and
  historical operating data are generated by `ml/` + `simulator/`.
- Work-zone map is a simplified 2D layout, not survey-grade GPS.
- We never use or claim access to real Caterpillar proprietary data.

## PREDICTED (model outputs, not ground truth)
- Task ETA, anomaly scores, machine health score/state.
- All carry `provenance: PREDICTED` and a fallback path.

## FUTURE REAL INTEGRATION (out of scope for the prototype)
- Real CAN-bus / VisionLink-style telemetry ingestion.
- Real GNSS + UWB proximity hardware.
- Real weather API.
- Instructor scheduling backend, LMS integration for training.

## Scale of synthetic dataset
- 50–200 operators, 20–50 machines, multiple sites and task types, weeks–months
  of correlated telemetry (see `ML.md` for correlation rules).
